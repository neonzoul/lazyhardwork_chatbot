# Lay v2 — engineering conventions (read before writing code)

Design of record: vault `Clients/000_lazyhardwork/PJ_lineOA_chatbot_v2/design-lay-v2.md` (folder may still be
`PJ_lineOA_chatcot_v1`). Platform limits: `doc/line-platform-notes.md`. This page is the short form every
implementer follows; the head engineer reviews against it.

## Branches and merges
- `main` = v1, live on Railway. **Never push to `main`** before the Tuesday cut-over.
- `v2` = integration branch. Feature branches are `v2-<module>` (git refuses `v2/<x>` while `v2` exists), each in
  its own worktree under `.worktrees/<module>` (ignored). One implementer per module; no two on the same files.
- Merge into `v2` only by the head engineer, after `npm test` is green in the branch. Small commits; messages say
  what changed and why; end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Layout (one responsibility per folder — see design §1.1)
```
src/line      LINE SDK wrapper (reply-or-push with sender, quick replies, loading, rich menu)
src/core      turn pipeline, debounce, session, lint (banned content / emoji / prose list), policy, errors, deps
src/brain     response schema, prompt builder, structured-output call, KB pack loader
src/cards     tokens, primitives, 7 templates, validate, render (+ plain-text fallback)
src/flows     opening, topics (follow-up map), fit, homework, endings, handoff, demo
src/identity  sender (Lay / Mos / demo shop), quiet window
src/discord   notify (threads, webhook fallback), relay bot, commands
src/leads     intake, export
src/store     sqlite db, migrations, repositories
knowledge/    GENERATED by scripts/kb-build.js — never hand-edit
tests/unit    node:test files  ·  tests/fakes  injected fakes  ·  tests/scenarios  YAML + run-scenarios.js
```
v1 files (`src/bot.js`, `src/llm.js`, `src/state.js`, the HTML admin) stay until the pipeline replaces them, then go.

## Code rules
- CommonJS, Node ≥ 22.13 (`node:sqlite`), no TypeScript, no build step. Dependencies: only what `package.json`
  already has plus `js-yaml` and `discord.js`; ask before adding anything else.
- **Everything external is injected** through `deps` (`src/core/deps.js`): `line`, `notifier`, `store`, `model`,
  `clock`, `log`. Modules never `require` the LINE SDK, OpenAI, axios or Discord directly except inside
  `src/line`, `src/brain/respond.js`, `src/discord`, `src/store`. That is what makes the scenario runner possible.
- The **model proposes, the code disposes**: prices, URLs, actions, state transitions, buttons and the sender are
  decided in code. A model output is data to validate, never an instruction.
- **Never silent**: every path that can throw is inside the turn's try/catch; a failure produces the honest fallback
  reply, never nothing.
- **Notify before promise**: the customer hears "ส่งให้มอสแล้ว" only after the notifier resolved.
- **Lint is the law** (`src/core/lint.js`): banned content, emoji policy, prose lists, markdown. Every outgoing text
  passes through it; tests assert on it.
- Thai customer-facing strings live next to the flow that uses them (`strings` objects), not scattered in templates.
  No `[Agent Lay]`, no stock closers, no email address, phone only via the profile line.
- Config from `process.env` only through `src/config.js`. Secrets never in code, logs or tests.
- Logging: `deps.log.info/warn/error(event, fields)` — one line per event, no customer text beyond 80 chars.

## Tests
- `npm test` runs `node --test tests/` (unit + fakes). Keep it under a minute; no network.
- `npm run scenarios` runs `tests/run-scenarios.js` over `tests/scenarios/*.yaml` with scripted model responses
  (deterministic) — the merge gate for anything that touches replies. `--model real` uses OpenAI (for QA).
- Fault injection is a first-class step (`fault:`) — notifier throw, model garbage, LINE 500.
- A PR that changes behaviour adds or changes a scenario.
